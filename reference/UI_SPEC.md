# Sapir Developer Hub v0.1 — интерфейс и продуктовая спецификация

> **Требования к интерфейсу.** Прочитай этот файл перед реализацией. `index.html`, `styles.css` и `app.js` составляют работающий интерактивный **референс интерфейса**, а не конечную архитектуру производства. Демо-данные не отражают текущее состояние корпоративных сервисов.

## 1. Назначение

Локальное desktop-приложение для сотрудников Sapir Game: задачи ClickUp, документация Outline, новости Slack и инструменты AI-агентов в одном быстром интерфейсе. Первый целевой дистрибутив: Windows x64, NSIS setup `.exe`, публикация через GitHub Releases. Техническая база реализации: **Tauri 2 + React + TypeScript + SQLite FTS5**. Нативную часть Tauri писать на Rust, сохраняя UI на TypeScript. Самостоятельный Node.js backend в runtime **не обязателен**, если интеграции и индексация реализованы через Tauri commands/plugins.

Это приложение **без собственной LLM**, без вызовов OpenAI/Claude/Gemini API, без корпоративного облачного backend Sapir Hub, без собственных логинов и учётных записей. Все обращения к API идут с устройства пользователя к существующим сервисам. Права на данные должны соответствовать правам подключённого пользователя.

## 2. Что считается реализованным в первой версии (MVP)

1. Desktop-shell Tauri со стабильным UI и навигацией, состояниями loading/empty/error и первым запуском без подключений.
2. Подключение ClickUp, Outline, Slack через поддерживаемые этими сервисами безопасные пользовательские механизмы. Реализовать только при наличии разрешений приложения и нужных OAuth scopes/API-токенов; если у Slack/Outline нужны администраторские разрешения, показывать объяснение.
3. Dashboard: краткий обзор моих задач, последних объявлений, быстрые действия.
4. My Tasks: список задач, фильтры статуса, поиск, карточка деталей и ссылка на исходную задачу. Изменение статусов можно отложить до следующей итерации.
5. Knowledge: дерево/список доступных пользователю страниц Outline, просмотр текста, быстрый полнотекстовый поиск по локальному индексу SQLite FTS5, копирование Markdown.
6. Knowledge Graph: интерактивная карта связей, извлечённых из структуры и явных ссылок документов. Первую версию графа можно сделать простой и без ML.
7. News: чтение последних разрешённых пользователю сообщений выбранного Slack-канала, прежде всего `#development`, и важных объявлений. Никаких прав на запись не требуется.
8. AI Agents: просмотр централизованного `AGENTS.md` из отдельного Git-репозитория, сравнение локальной и доступной версий, diff, установка файла в выбранный Unity-проект, безопасное обновление; поддержка `CLAUDE.md` с импортом `AGENTS.md`.
9. Prompt Builder: детерминированные шаблоны, выбор задачи и документов, предпросмотр, копирование; без AI API.
10. Settings: подключения, локальные данные, состояние синхронизации, выбор локальных Unity-проектов, проверка обновлений.
11. Нижняя кнопка «Нашли проблему или баг?» открывает личный Slack DM с руководителем разработки по корпоративной ссылке, которую необходимо указать в конфигурации. Не вставлять несуществующий Slack ID.
12. Глобальный поиск по `Ctrl+K`: локальная навигация по разделам, задачам и документации. Поддерживать также `Cmd+K` для будущей macOS.

## 3. Навигация и экраны

### Левая панель

**Рабочее пространство:** Обзор, Мои задачи, База знаний, Новости отдела.

**Инструменты AI:** AI Agents, Prompt Builder.

**Низ:** Настройки, Нашли проблему или баг?, локальный статус/профиль.

### Обзор (`home`)

- Hero с фирменным огранённым синим сапфиром Sapir Game.
- Счётчики активных задач, доступных документов, объявлений, обновлений инструкций.
- Последние задачи с переходом к карточке, последние новости Slack.
- Быстрые действия: Knowledge, AGENTS.md, Prompt Builder.
- **Без подключений** счётчики не должны показывать вымышленные успешные данные. Отображать `Connect your services`.

### Мои задачи (`tasks`)

- Tabs: Все, К выполнению, В работе, На ревью, Готово (сопоставление реальным статусам ClickUp конфигурируемое).
- Поиск по названию и ID.
- Таблица: задача/ID, статус, приоритет, проект, дедлайн.
- Клик: подробное описание, ссылки, связанные документы, кнопка «Собрать промпт».
- Задачи отображать только в рамках полномочий пользователя.

### База знаний (`knowledge`)

- Поисковое поле (локальный индекс, не API-запрос на каждый символ).
- Переключение «Документы» / «Граф знаний».
- Список доступных страниц, просмотр Markdown/HTML как текста, теги, ссылки.
- Копирование текущего документа как Markdown.
- Граф на основании реально доступных ссылок, без AI-классификации.
- При отсутствии локального индекса: предложение первичной синхронизации.

### Новости отдела (`news`)

- Хронологическая лента разрешённых сообщений Slack.
- Для каждого элемента: автор, канал, дата и время, текст, ссылки, при необходимости вложения.
- Не показывать сообщения, которые текущий пользователь не вправе читать.

### AI Agents (`agents`)

- Единый **корпоративный файл `AGENTS.md`**, подготовленный Head of Development на основе утверждённой архитектуры Sapir Game.
- Source of truth: Git (предположительно отдельный приватный Git-репозиторий стандартов).
- Раздел показывает: текущую доступную версию, локальную версию, Markdown-превью, diff, установленные проекты, состояние синхронизации.
- Установка в указанные пользователем локальные Unity-проекты. Не изменять другие файлы и не перезаписывать локальные изменения без предварительного просмотра.
- `CLAUDE.md` может импортировать `@AGENTS.md` для Claude Code; перед релизом проверить актуальный формат импорта в используемой версии Claude Code.
- Корпоративные правила обновляются **отдельно от релизов самого Hub**. Изменение `AGENTS.md` не инициирует пересборку Tauri.
- В MVP **не нужен** встроенный корпоративный редактор правил с push в Git. Редактирование стандарта происходит в GitHub/Rider, а Hub только получает обновления.
- Git-клиент пользователя должен обладать правом чтения репозитория. Не вшивать общий GitHub Personal Access Token в приложение.

### Prompt Builder (`prompts`)

- Выбор шаблона: Implement, Code Review, Investigate Bug (с возможностью расширения).
- Выбор доступной задачи ClickUp и релевантных документов Outline.
- Генерация текстового промпта **обычными строковыми шаблонами**, без LLM.
- Предпросмотр и кнопка копирования.
- Явное предупреждение, что вставка текста в сторонние AI-сервисы может привести к отправке корпоративных данных третьей стороне. По возможности подсвечивать секреты до копирования.

### Настройки (`settings`)

- Подключение/отключение личных учётных данных сервисов.
- Git-источник корпоративного `AGENTS.md` и список локальных проектов.
- Состояние локального индекса/последняя синхронизация и очистка кэша.
- Проверка обновлений Hub и отображение версии приложения.
- Информация о безопасности и пользовательских разрешениях.

## 4. Дизайн-система

### Цвета

- Базовый фон: `#111319` (фирменный тёмный фон).
- Sidebar: `#151820`.
- Карточки: `#1A1E27`, `#202531`.
- Границы: `#2B303C`.
- Текст: `#EDF2FB`, вторичный текст `#9099AA`.
- Акцент: сапфировый `#77ACFF`, мягкие синие градиенты.
- Состояния: зелёный `#74D5AD`, янтарный `#E4BD77`, фиолетовый `#C7A2F4`.

### Принципы

- Desktop-first, адаптивность до узких размеров окна.
- Тёмный, эстетичный интерфейс без чрезмерной декоративности.
- Sidebar слева, верхняя строка с контекстом и поиском, основной контент карточками.
- Клавиатура: `Ctrl+K` / `Cmd+K`, Escape для закрытия окон, видимые focus states.
- Быстрые переходы, читаемый текст, состояние каждого действия.
- На экранах loading/empty/error не рисовать фиктивные успешные цифры.
- Чистый HTML в WebView, не рендерить документы на Canvas. Это позволяет агентам читать содержимое при наличии разрешённых средств доступа.
- Движение умеренное, уважать `prefers-reduced-motion`.

## 5. Что важно для Codex и Claude Code

Нужно обеспечить два отдельных способа машинного чтения информации:

1. **Файловый:** экспорт Markdown с выбранными материалами и корпоративный `AGENTS.md` в файловой системе проекта. Это приоритет MVP.
2. **Опциональный HTTP (последующая версия):** если решим добавлять `/docs/:id.md`, `/tasks/:id.md`, локальный сервер слушает только `127.0.0.1`; нужна аутентификация локальных клиентов, проверка Origin/CSRF и исключение экспорта недоступных данных. Наличие URL `localhost` само по себе не обеспечивает безопасность.

MCP в v0.1 не нужен. Не добавлять его без отдельной задачи. Нельзя считать, что облачный Codex автоматически имеет доступ к localhost на компьютере разработчика.

## 6. Локальное хранилище, sync и безопасность

- SQLite для метаданных, кеша Outline, ClickUp, Slack; FTS5 для индекса доступных документов.
- Российские тексты и поисковые запросы: проверить особенности токенизации FTS5; для морфологии может потребоваться отдельное расширение или нормализация.
- Пользовательские токены хранить в защищённом хранилище ОС. В SQLite и логах токенов быть не должно.
- Отключение сервиса/утрата прав: очистка или ограничение доступа к соответствующим кэшированным данным; удаление по явному запросу пользователя.
- Синхронизация в фоне только при запущенном приложении, с ограничением запросов, backoff на `429` и понятным индикатором ошибок.
- Slack API: состав допустимых scope и способ доступа к нужному каналу согласовать с администраторами workspace; личные права не обходить.
- Ссылки на Slack DM должны быть настраиваемыми, не вшивать персональные данные в публичный репозиторий.
- Отдельный пароль/аккаунт Hub не нужен, но локальный HTTP-доступ и экспорты обязаны иметь продуманную безопасность.

## 7. Релизы и независимые обновления

**Обновление самого приложения:** Tauri build → Windows NSIS installer `.exe` → GitHub Releases. Через Tauri updater можно распространять подписанные обновления, JSON-манифест и уведомления. При приватных GitHub Releases заранее продумать авторизованное скачивание, не хранить общий токен внутри exe. В первой итерации допустим ручной апдейт с уведомлением о доступной версии.

**Обновление корпоративных инструкций:** Hub регулярно проверяет Git-источник; сравнивает хеш/версию; показывает diff; по подтверждению синхронизирует `AGENTS.md` в выбранные проекты. Это не требует нового релиза Hub. Изменённые локально инструкции без согласия не затирать.

## 8. Предлагаемая архитектура production

```text
src/                                 # React/TypeScript
  app/                                # Router, providers, window layout
  pages/                              # Home, Tasks, Knowledge, News, Agents, Prompts, Settings
  components/                         # Sidebar, Topbar, SearchPalette, Cards, Dialogs, States
  features/                           # Organized by feature
    tasks/
    knowledge/
    news/
    agents/
    prompts/
    settings/
  shared/                             # UI tokens, types, utilities, contracts
src-tauri/                            # Tauri 2 / Rust
  src/commands/                       # Typed native commands
  src/integrations/                   # ClickUp, Outline, Slack, Git
  src/storage/                        # SQLite, FTS, sync metadata
  src/security/                       # Secure secrets and permissions
```

Структура **ориентировочная**; минимизируй ненужные слои. Общие интерфейсы доступа к данным нужны, чтобы UI не зависел от конкретного API-сервиса. Используй typed DTO для Tauri commands, проверку ошибок и отмену запросов.

## 9. Порядок реализации

1. Воспроизвести этот UI на React + TypeScript, ввести компоненты и токены.
2. Упаковать в Tauri, настроить Windows dev/build, сохранить рабочий MVP без сети.
3. Сделать настройки и защищённое хранение пользовательских подключений.
4. Outline: чтение, локальное сохранение, Markdown, FTS5, дерево, граф.
5. ClickUp: мои задачи и детали.
6. Slack: чтение новостей `#development`.
7. AI Agents: Git source, сравнение, diff, безопасная установка в проекты.
8. Prompt Builder: шаблоны из реальных доступных данных и ручной экспорт.
9. Тестирование offline/error/empty, доступность интерфейса, инкрементальная синхронизация.
10. GitHub Actions, NSIS Release, политика обновлений.

## 10. Критерии приёмки MVP

- Разработчик устанавливает программу без Node/Rust на своём устройстве.
- Первое открытие не требует регистрации в самом Hub.
- Без подключений показываются честные пустые состояния и предлагается настройка сервисов.
- Вход по своей учётной записи в каждом сервисе не раскрывает чужие документы/задачи.
- Поиск на локальном индексе не обращается к Outline на каждое нажатие клавиши.
- `Ctrl+K` открывает командный поиск, документы читаются в нормальном HTML и экспортируются как Markdown.
- Корпоративный AGENTS.md можно установить в локальный Unity-проект, проверить изменения и обновить без выпуска нового `.exe`.
- Существующий изменённый AGENTS.md нельзя перезаписать молча.
- Claude Code получает тот же набор правил, что и Codex.
- Prompt Builder работает без LLM и не отправляет данные в AI API.
- Кнопка баг-репорта открывает настраиваемый личный DM в Slack.
- Собирается Windows x64 NSIS installer через GitHub Actions.
- Все демо-данные удалены или помечены перед релизом production.

## 11. Что пока НЕ делать

- Общий облачный backend Sapir Developer Hub.
- Собственную систему аккаунтов/ролей Hub.
- Локальную или облачную AI-модель в runtime.
- Полноценный MCP-сервер.
- Систему тикетов на баги внутри Hub.
- Полноценный редактор AGENTS.md с записью обратно в корпоративный Git.
- Многопользовательские профили или рейтинги сотрудников.
- Сложную геймификацию; её можно добавлять позже как отдельные простые onboarding milestones.

## 12. Прототип: интерактивность, которую нужно сохранить

- Навигация в sidebar.
- `Ctrl+K` с поиском задач, документов и разделов.
- Фильтр задач и карточка деталей.
- Поиск Outline, просмотр документа, граф связанных статей.
- AI Agents: preview, diff, обновление, проектные установки.
- Prompt Builder: настройки и live-preview.
- Демонстрационные модальные окна и toast-состояния заменить настоящими в рамках возможностей сервисов.

### Важное напоминание

**Референс показывает желаемые экраны, но не разрешает выдумывать API, права доступа, реальные Git-версии или Slack ID.** Уточняющие конфигурационные данные разработчик должен задать в настройках приложения или получить через официальные API по правам пользователя.
